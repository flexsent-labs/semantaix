# Semantaix — Data Models (SQLite, system of record)

_Generated by BMAD `document-project`, 2026-06-19. Each concern owns one SQLite file under
`.data/`. There is **no RDBMS on the runtime path**; SQLite is the durable system of record. All
access is funneled through `*Repository` classes (~37) — no raw SQL outside repositories._

## WAL / cross-process reads

`operator_files`, `knowledge`, and `web_auth` DBs run in **WAL mode** so the api service can open
them read-only (and `ATTACH` the knowledge DB to the operator-files DB in a single query — see
`services/api/app/operator_files_view.py`) while the owning service writes.

## Notable data invariants

- **RAG chunks**: SHA-256 content dedup; optional `is_confidential` / `project_id`; trace lineage
  uses stable `rag_chunks` ids (no external vector id).
- **`answer_traces`**: written at decision time (retrieval hits+scores, guardrail outcome, model
  routing, confidence, `hitl_ticket_id`); **append-only** — corrections never rewrite past traces.
- **Calendar tokens**: refresh tokens **Fernet-encrypted at rest**, upsert on `(project_id, operator)`.
- **`project_services`**: `UNIQUE(project_id, lower(name))`; calendar-eligibility is a row predicate
  (`duration_minutes IS NOT NULL`), not a separate table.
- **Tenant scoping**: NL ops sessions/versions/audit logs carry `tenant_id`; **answer_traces do
  not** (global) — a known asymmetry.
- **Timezone discipline**: all stored datetimes UTC ISO-8601; converted at the edge via `zoneinfo`.

## Migrations

Schema creation/migration is **idempotent, code-driven** inside each repository (existence-check
guards via `sqlite_master` / `PRAGMA table_info`); fresh-deploy creates final schema directly.
There is no external migration tool (no Alembic) — repositories own `CREATE TABLE IF NOT EXISTS`.
