# Semantaix — Development Guide

_Generated by BMAD `document-project`, 2026-06-19._

## Prerequisites

- **Python 3.11** (required — ruff `target-version = py311`; resolver scripts need 3.11+ `tomllib`).
- Docker + Docker Compose (for the full stack).
- Secrets: OpenRouter API key, Telegram bot token, operator chat IDs, Google OAuth client (for
  calendar), Fernet encryption key.

## Local setup

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env        # fill in secrets
```

New runtime deps → `requirements.txt`; dev-only → `requirements-dev.txt`. New env vars need **both**
a `.env.example` entry **and** a `Settings` field (`platform_common/settings.py`) — never scatter
`os.getenv`.

## Commands

```bash
ruff check .                                              # lint (sole authority; line length 100)
pytest --cov --cov-config=.coveragerc --cov-report=term-missing   # 100% gate on platform_common/ + services/
pytest tests/test_foo.py -v                               # single file
pytest -m e2e                                             # e2e suite (CI runs this too)
docker compose up --build -d                              # full stack
bash scripts/run_all_epic_feature_signoffs.sh            # CI parity + live demo
bash scripts/epic16_signoff.sh                           # operator registration signoff
```

## Testing rules (load-bearing)

- **100% coverage is a hard CI gate** (`fail_under = 100`). Every new branch — including each
  `_skip`/`return None`/error path — needs a test. Avoid `# pragma: no cover` unless truly unreachable.
- **Test files mirror source** under `tests/` (`answerers/weather_client.py` →
  `tests/test_answerers_weather_client.py`). Async tests use `pytest-asyncio` (function-scoped loop).
- **Mock httpx, never hit the network.** Inject the http client and a frozen `now`; drive error
  branches explicitly (401→refresh→retry, refresh-then-still-401, 429 `Retry-After`, 5xx).
- **Repositories test against a tmp `db_path`** — never the real `.data/` files.
- **E2E** uses FastAPI `TestClient` with markers `@pytest.mark.e2e`, `@pytest.mark.epic("NN")`,
  `@pytest.mark.story("NN-0X")`. Stub LLM + Telegram sender on module-level singletons via
  `monkeypatch.setattr(..., AsyncMock(...))`.

## Coding conventions

See `_bmad-output/project-context.md` (67 rules) — the authoritative AI ruleset. Highlights:

- `from __future__ import annotations` atop every module; PEP 604 unions.
- Interfaces are `typing.Protocol`; deps constructor-injected; public methods keyword-only.
- Value objects `@dataclass(frozen=True)`. Repos own all DB access; class names end `Repository`.
- Per-layer failure convention (answerers skip, repos raise typed errors, endpoints `HTTPException`).
- Network async / SQLite sync via `asyncio.to_thread`. Time injected. Secrets from `Settings` only.

## Workflow / process rules

- **CI gate** = `ruff check .` then `pytest` (coverage) + `pytest -m e2e` on every PR and push to main.
- **One PR per story**; small reviewable units mapping 1:1 to `create-story → dev-story →
  code-review → PR`. Don't batch stories.
- **One feature epic in implementation at a time** (BMAD feature-sequential rule); next starts only
  after the prior's tests pass + regression + demo/acceptance signoff.
- Each story ships tests + a signoff artifact under `_bmad-output/implementation-artifacts/`.

## ⚠️ Test-isolation gotcha (recurring)

Tests have historically leaked into the default-project `.data/` state (calendar/services), breaking
`pipeline_journey` and epic-13 catalog tests. New singleton repos need a global autouse `db_path`
reset; `get_settings()` can leak to the default `.data/` under setattr-based settings patching. Use
tmp `db_path` everywhere. (See most recent commit `475b3d6` "Fix platform-admin test isolation".)
