# Semantaix — API Contracts

_Generated by BMAD `document-project`, 2026-06-19. ~157 endpoints across services. Request/response
bodies are Pydantic models; endpoints are thin, logic lives in modules/repositories. Service-to-
service calls authenticate with `internal_service_token` (Bearer). The list below is the **api**
service surface (115 routes); `web_ui` (37) renders admin HTML, `user_gateway` (4) handles
Telethon QR/2FA auth, `bot_gateway` (1) is the Telegram webhook._

## Authentication modes

| Mode | Used by | Mechanism |
|---|---|---|
| Cookie session | Browser (web_ui → api) | `semantaix_session` `HttpOnly; SameSite=Lax`; issued by `/admin/auth/verify` (Telegram 6-digit code, 5-min TTL, 5-attempt cap); revoke-based (never expires) |
| Internal service token | bot_gateway/web_ui → api | `Authorization: Bearer <internal_service_token>` (+ `as_user=` for acting-as) |
| OAuth `state` (CSRF) | Google → api calendar callback | single-use `state`, the sole browser↔operator binding |

## Core conversation

| Method | Path | Purpose |
|---|---|---|
| POST | `/conversations/inbound` | **Single entry point** for every customer message. Builds `AnswerContext`, runs the 4-answerer pipeline, escalates to HITL on no-answer. Accepts `delivery_channel` (`bot` \| `operator_user` + `operator_id`). Idempotent inbound (epic 12 hardening). |
