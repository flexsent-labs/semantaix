# Semantaix — Deployment Guide

_Generated by BMAD `document-project`, 2026-06-19._

## Topology

Docker-first. `docker compose up --build -d` brings up the full stack:

| Container | Role |
|---|---|
| `nginx` (80) | Reverse proxy: `/api`→api:8000, `/admin`→web_ui:8001, `/telegram/webhook`→bot_gateway:8002, `/health/live` local 200 |
| `api` (8000) | Core business logic |
| `web_ui` (8001) | Admin shell |
| `bot_gateway` (8002) | Telegram webhook ingress |
| `user_gateway` (8005) | Telethon MTProto sessions |
| `ingest_worker` (8003) / `scheduler` (8004) | Heartbeat placeholders |
| `telegram_bot_api` | Self-hosted Telegram Bot API server |
| `qdrant` (6333) | Provisioned, **not on runtime path** (lemma-overlap retrieval is used) |
| `postgres` | Behind `--profile with-postgres`; **inactive**, no driver imported |

Named volumes: `app_data` (the `.data/` SQLite files — the system of record), `qdrant_data`,
`postgres_data`, `operator_uploads`, `whisper_cache`, `telegram_bot_api_data`.

## Environments

- **Local/dev:** `docker-compose.yml`.
- **Production (DigitalOcean VPS):** `docker-compose.prod.yml` overlay (see README "DigitalOcean").
  Live ingress historically: ngrok/public → nginx → bot_gateway. **Operational note (memory):** a
  stale upstream IP once produced an nginx 502 that silently took the bot down — check nginx logs
  FIRST on a silent bot.

## CI/CD

`.github/workflows/`:

| Workflow | Purpose |
|---|---|
| `ci.yml` | `ruff check .` then `pytest` with coverage (`fail_under=100`) + `pytest -m e2e`, on every PR and push to main |
| `deploy.yml` | Deployment automation |
| `loc.yml` | Updates the README LOC badge (`[skip ci]` commits) |

## Health & readiness

Every service exposes `/health/live`, `/health/ready`, `/health/startup` (via `app_factory`).
Readiness includes `qdrant_url` reachability even though Qdrant is not queried at runtime.

## Data durability & backup

- SQLite files in the `app_data` volume (`.data/`) are the durable system of record.
- **Backups** (`backups.py`): tar.gz archives of the SQLite files (not Qdrant snapshots), recorded
  in `semantaix_backups.db` with a `backup_events` audit trail. Restore requires a confirmation
  token and is surfaced in the Web UI.

## Secrets

All via env → single `Settings` (122 fields): `openrouter_api_key`, `telegram_bot_token`,
operator/admin chat IDs, `internal_service_token`, Google OAuth `client_id/secret/redirect`,
Fernet `calendar` encryption key. Never committed, never logged. Per-operator calendar refresh
tokens are Fernet-encrypted at rest in `semantaix_calendar.db`.

## Rebuild

A project `rebuild` skill exists for restarting/redeploying the live stack after merging to main.
